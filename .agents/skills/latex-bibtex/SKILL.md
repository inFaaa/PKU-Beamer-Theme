# LaTeX 参考文献

把用户指定的真实文献整理成与项目兼容的 BibTeX，并保留可追溯的来源。
使用当前环境可用的检索、文件编辑和 TeX 编译能力，不依赖特定插件或 API。

## 确认目标

- 读取用户给出的题名、DOI、链接或现有条目，确认要新增、查错还是去重。
- 先检查主 `.tex`、目标 `.bib`、引用命令和现有构建方式，沿用 BibTeX 或 biblatex/Biber。
- 在工作区检索引用键的使用位置；只修改本次涉及的条目和必要引用。
- PKU-Beamer-Theme 的示例文献位于 `ref.bib`；其他项目沿用实际文献文件，不额外清理任务范围外的示例。

## 查证文献

- 优先用 DOI 定位出版方记录；没有 DOI 时，以题名和作者组合寻找准确记录。
- 计算机领域可读取 DBLP 记录及其 BibTeX；出版方页面、Crossref 和 arXiv 原始记录也可作为依据。
- 核对作者顺序、完整题名、年份、期刊或会议、卷期页码、DOI 和文献版本。
- 不凭搜索摘要或记忆补全这些字段；同名论文需要进一步核对作者和摘要等身份信息。
- 预印本、会议版、期刊扩展版分别识别，保留用户实际引用的版本。
- arXiv 更新时间不直接充当正式发表年份；会议年份也不从网页访问日期推断。
- 来源冲突时记录冲突，按目标版本的原始发布记录判断；无法判断的字段先保留或留空。
- 无法联网时可整理语法和用户已有信息，但明确标注“未在线验证”，不得制造作者、年份、venue 或 DOI。

## 写入与去重

- 优先采用权威来源导出的 BibTeX，再按项目样式做必要清理。
- 保留已有且仍有效的元数据，包括 DOI、URL、eprint、archivePrefix、版本或访问日期等。
- 保持已有引用键稳定；不要批量重命名被正文引用的 key。
- 新 key 沿用项目习惯并检查冲突；发现同 key 不同论文时先区分身份。
- 先比较规范化 DOI，再检查 arXiv 标识与版本、题名及作者，不能仅凭题名相似就删除条目。
- 合并同一文献的重复记录时保留有效字段，并同步本次受影响的引用；不同发表版本不自动合并。
- 条目类型依据真实文献和当前后端选择；不能把网页、软件或其他非论文材料改成 `@inproceedings` 来消除警告。
- 遇到缺失作者或年份，不填入猜测值；保留有依据的原值，并向用户说明缺项。
- 保留姓名中的重音、大小写和机构作者；仅给确需保护的缩写或专名加花括号。

## 检查与交付

- 检查括号配对、重复 key、必要字段和正文引用是否能解析。
- 有可用 TeX 环境时沿用项目编译流程；BibTeX 项目通常需要 LaTeX、BibTeX、再两次 LaTeX。
- 检查日志中的未定义引用和文献错误，并检查生成的参考文献页是否被截断。
- 缺少编译工具时说明验证范围，不把静态检查描述成编译成功。
- 简要报告修改文件、采用的版本、核对来源链接，以及仍未验证的字段。
- 用户只要求提供条目时直接交付 BibTeX，不修改项目文件。

## 可选资料

[DBLP](https://dblp.org/) 可用于定位计算机论文与导出记录；不要求每篇文献都经过此站。
